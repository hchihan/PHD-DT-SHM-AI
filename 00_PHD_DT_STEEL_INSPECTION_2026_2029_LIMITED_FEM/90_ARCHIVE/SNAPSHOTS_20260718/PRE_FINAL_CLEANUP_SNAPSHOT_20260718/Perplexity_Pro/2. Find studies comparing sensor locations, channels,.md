# Find studies comparing sensor locations, channels, or sensor combinations

## Direct evidence: sensor configuration compared under identical protocol

### Wheat et al., 2024 – "Impact of Data Leakage in Vibration Signals Used for Bearing Fault Diagnosis" (IEEE Access)

- DOI: 10.1109/ACCESS.2024.3497716.[^1][^2]
- Year/venue: 2024, IEEE Access.[^1]
- Study object: Bearing fault diagnosis using vibration signals, explicitly investigating domain shifts (including sensor/operating-condition changes) that arise from improper train/test partitioning.[^2]
- What they do: Systematically test how classification accuracy is inflated or degraded when data leakage occurs across splits (e.g., segments of the same sensor recording or operating condition leaking between train and test), holding the classifier fixed.[^2]
- Directly supported claim: Leakage-controlled evaluation protocols are essential — accuracy estimates under naive (leaky) splits can be substantially higher than under leakage-controlled splits, and this effect can dominate whatever gains come from a different sensor or model choice.[^2]
- Limitation: Focuses on leakage/domain-shift methodology rather than directly ranking sensor locations; does not isolate sensor-position effects from architecture effects in a single ablation table.[^2]
- Reason for inclusion: METHODOLOGICAL EVIDENCE — directly relevant to your "identical and leakage-controlled evaluation protocol" requirement; demonstrates why leakage control is necessary before any sensor-vs-architecture comparison is credible.


### Rajabioun et al., 2025 – "Optimal Source Selection for Distributed Bearing Fault Classification" (Applied Sciences)

- DOI: reported in MDPI Applied Sciences 15(19):10631.[^3][^4]
- Year/venue: 2025, Applied Sciences (MDPI).[^3]
- Study object: Distributed bearing faults; multiple candidate input signal sources (sensor channels) evaluated for classification accuracy using wavelet-transform features and machine-learning classifiers, held constant across source combinations.[^3]
- What they do: Compare accuracy across different combinations of input sources (sensor channels) under the same feature-extraction and classification pipeline, i.e., an identical-protocol ablation over sensor combination rather than model architecture.[^3]
- Directly supported claim: Selecting the right combination of signal sources materially changes classification accuracy, supporting the idea that sensor/channel choice is a first-order factor even when the model is unchanged.[^3]
- Limitation: The full paper text was not directly retrievable, so exact effect sizes versus architecture changes and details of leakage control could not be confirmed from the abstract alone. Treat findings as preliminary until the full text is checked.
- Reason for inclusion: DIRECT EVIDENCE (tentative) — closely matches "sensor combination" comparison under fixed protocol, though verification of leakage control is still needed.


### Distributed bearing fault classification with multi-sensor input ablation (YYU group, 2025)

- Two related papers: "Classification of Distributed Bearing Faults Using a Novel Sensory Board and Deep Learning Networks With Hybrid Inputs" and "Distributed Bearing Fault Classification of Induction Motors Using 2-D [deep learning]".[^5][^6]
- Year/venue: 2025, journal publications (GCRIS/Elsevier).[^6][^5]
- Study object: Induction motor bearings; six signal sources (3-axis vibration, stray magnetic flux, 2-phase current) at 50 operating points (10 speed × 5 torque levels).[^6]
- What they do: Hold the deep-learning architecture fixed and systematically vary which subsets of the six sensor sources are fed into the model, comparing accuracy across combinations; separately, they compare the deep architecture against SVM and XGBoost on the same sensor inputs.[^5][^6]
- Directly supported claim: "The model performs at its best when all six input sources are utilized," and their comparison table shows accuracy varies more across sensor-source subsets than between the deep learning model and SVM/XGBoost on the same inputs — i.e., sensor/channel combination has a larger effect than model architecture in their results.[^5][^6]
- Validation method: Train/test split evaluation repeated across 50 operating points; robustness checked via held-out test data.[^5]
- Limitation: Does not explicitly discuss cross-run leakage controls (e.g., whether operating points overlap between train/test); the "identical protocol" claim rests on using the same split methodology across all sensor-subset and model comparisons, not necessarily on a rigorously leakage-audited pipeline.[^6][^5]
- Reason for inclusion: DIRECT EVIDENCE — one of the clearest available ablations of sensor combination vs. architecture, with quantitative accuracy differences reported for both factors.


## Uncertainty methods for small numbers of independent runs

### Jiang \& Simon, 2007 – "A comparison of bootstrap methods and an adjusted bootstrap approach for estimating the prediction error" (Statistics in Medicine)

- DOI: 10.1002/sim.2968.[^7]
- Year/venue: 2007, Statistics in Medicine.[^7]
- Study object: Classification with very small sample sizes (microarray data, n far smaller than feature count), directly analogous to a small-number-of-runs vibration setting.[^7]
- What they do: Compare leave-one-out bootstrap, 0.632+ bootstrap, and leave-one-out cross-validation, then propose a repeated leave-one-out bootstrap (RLOOB) and an adjusted bootstrap (ABS) that fits a learning curve across bootstrap sample sizes to correct for bias.[^7]
- Directly supported claim: With small n, standard bootstrap and cross-validation estimators show substantial bias or variance; the ABS method gives a more robust (slightly conservative) prediction-error estimate without the large upward bias of leave-one-out bootstrap or the high variance of leave-one-out CV.[^7]
- Limitation: Developed for microarray gene-expression classification, not vibration data; adaptation to time-series/vibration segments with autocorrelation would need care to preserve independence assumptions.[^7]
- Reason for inclusion: METHODOLOGICAL EVIDENCE — directly addresses confidence-interval/bootstrap estimation when the number of independent samples (here, "runs") is small, transferable to your comparison of few experimental runs.


### Combining bootstrap samples across independent trials/splits (applied ML practice)

- Source: Cross Validated discussion on combining bootstrap confidence intervals from multiple independent train/test splits.[^8]
- What it shows: When you have several independent experimental splits (runs) from the same underlying distribution, you can pool the individual bootstrap samples from each run into one combined empirical distribution and take quantiles of the pooled set to get a single, sharper confidence interval — rather than reporting per-run intervals separately.[^8]
- Directly supported claim: This pooling approach is valid specifically when test sets/runs are independent and drawn from the same distribution, which matches a leakage-controlled multi-run vibration experiment.[^8]
- Limitation: Informal community source (not peer-reviewed), so treat as a practical heuristic rather than a validated statistical method; assumes exchangeability of runs which must be checked (e.g., consistent sensor/operating conditions).[^8]
- Reason for inclusion: METHODOLOGICAL EVIDENCE (supplementary) — practical guidance for combining sparse independent runs into a usable confidence interval.


### Bootstrapping out-of-sample predictions for efficient performance estimation

- Source: "Bootstrapping the out-of-sample predictions for efficient and accurate cross-validation" (PMC, 2018).[^9]
- What it shows: Proposes bootstrapping out-of-sample predictions collected across cross-validation folds to build more efficient, lower-variance estimates of performance and its uncertainty than naive per-fold statistics, particularly useful when the number of folds/runs is limited.[^9]
- Directly supported claim: Bootstrapping over pooled out-of-sample predictions (rather than per-run summary statistics) increases the effective sample size for uncertainty estimation even with few independent CV runs.[^9]
- Reason for inclusion: METHODOLOGICAL EVIDENCE — complements Jiang \& Simon by giving a CV-integrated bootstrap procedure for small-run settings.
